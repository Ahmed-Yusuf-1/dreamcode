**Guardrails (do not regress):** the learner writes and runs real code at every step
(Python via Pyodide, JavaScript in a worker, TypeScript type-checked then run in the
same worker, DOM lessons in a sandboxed iframe; C# is read + quiz until a sandbox
lands). Spaced review stays FSRS. The AI guide asks questions, never gives answers.
Voice: no em or en dashes, no single-character ellipsis, no decorative emoji.
Runtime database access stays RLS-scoped through the anon key and the learner's
session; XP and awards change only through the database functions. Every piece of
runnable content has a reference solution and passes `npm test`.

## 2. Engineering follow-ups

- **Handle moderation.** Handles are learner-chosen text shown to everyone. The
  database reserves the names that would let someone pass as staff or the product,
  and the format is limited to `[a-z0-9_]{3,20}`, but there is no profanity filter
  and no way to report or rename a handle. Before the leaderboard is busy, add a
  block list and an admin path to rename one, and decide whether a new handle needs
  a cool-down so people cannot swap identity every day.

- **Signed-in browser tests.** The Playwright suite covers guest flows on desktop and
  mobile, including earning a badge and wearing it. Add a CI job with a dedicated
  Supabase test project (URL, anon key and a test user in repository secrets) that
  signs in, completes an activity, checks the award is server-side and idempotent,
  claims a handle, and sees itself on the leaderboard. The rules themselves are
  already covered against a real Postgres by `npm run test:db`.
- **Durable rate limiting.** `src/lib/rateLimit.ts` is per-process memory. For a
  global cap on serverless hosting, back it with Upstash Redis or Vercel KV (adds an
  external service, so an owner decision).
- **Next patch.** Move from 16.2.9 to the current 16.2.x after reading the bundled
  upgrade notes, then re-run every gate. The PostCSS advisory inside Next clears only
  when Next ships a patched copy; never run `npm audit fix --force`.
- **Night review reminders.** The Profile setting is honestly marked unavailable.
  Real reminders need notification permission, timezone rules and a scheduler (push
  or email).
- **Install-script approval.** `npm install-scripts ls` lists `unrs-resolver`
  (an ESLint resolver dependency) as awaiting approval. Lint works without it;
  approve or deny it deliberately.

- **Leaderboard at scale.** `leaderboard()` ranks every opted-in profile on each
  call. That is right for now (indexes on `xp` and `week_xp` cover it), but past a
  few thousand learners it should become a periodically refreshed materialized view,
  or a cached top-100 with the caller's standing fetched separately.

## 5. Code execution sandbox (C# and Rust)

**Why.** Python, JavaScript and TypeScript run in the learner's own browser, free and
with no server risk. C# and Rust have no practical in-browser runtime, so running and
grading their code needs a server that executes untrusted code in isolation (no
network, no filesystem escape, CPU, memory and time limits). One sandbox unlocks
both languages.

**Shape.** A signed-in, rate-limited `/api/run` route (modelled on `/api/guide`)
takes `{ language, code, stdin }`, forwards it to an execution service and returns
`{ stdout, stderr, compileOutput, status, time, memory }`. Challenges wrap the
learner's function in a harness per test, the same way `src/lib/grader.ts` does in
the browser. Keep it provider-agnostic (`RUN_PROVIDER`, `RUN_BASE_URL`,
`RUN_API_KEY`) and behind a flag. Then mark C# lessons `runnable: true`, give them
starters and tasks, add reference solutions, and extend `npm test` to call the same
runner.

**Providers (check current pricing before committing):**

- **Judge0.** Open source, 60+ languages including C# and Rust. Self-host the
  Community Edition with Docker on a small VPS (software free, hosting roughly
  $5-20 a month), or use the managed RapidAPI plans (small free tier, paid tiers for
  volume).
- **Piston.** Open source and self-hostable, lighter than Judge0. The public
  instance is rate limited and not for production.
- **Sphere Engine.** Commercial and managed. Enterprise pricing.
- **Roll your own** containers or microVMs. Most control, and all of the security
  work is yours. Not recommended without a strong reason.

**Recommendation.** Prototype on Judge0's RapidAPI free tier to prove `/api/run` and
grading end to end, then either upgrade that plan or self-host Judge0 CE. This adds
an external service, a recurring cost and an untrusted-code surface, so it is an
owner decision.
